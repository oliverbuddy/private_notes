# 2026-10-31

## 小记 App（xiaoji）— 立项与首版骨架

用户想做「本地优先 + Markdown」的移动端小记应用，对标语雀小记。经过三轮讨论确定：

- 平台：**手机端**（不是桌面），技术栈定为 **Flutter**
- 存储：**全部本地**，md 文件为唯一数据源，不放数据库
- Markdown 定位：**既要编辑也要存储**（承认语雀小记的编辑框就是 markdown 富交互，源码即内容）
- 范围：删除所有依赖服务端的能力（分享链接、知识库/生成文档、书签 OG 抓取、版本历史、批量操作）；保留无标题快速记录、时间线、标签、待办、图片、链接、回收站、置顶、归档、搜索、导出

### 关键设计决策

1. **不引入 SQLite**。几千条以内用「启动全量读盘 + 内存过滤」更快更少 bug。换索引的触发条件是启动 >1s 或搜索掉帧（约 3000 条）。
2. **Markdown 编辑器只改样式不改文本**。自定义 `TextEditingController.buildTextSpan` 做行级（标题/列表/待办/引用/代码块）+ 行内（粗体/斜体/代码/链接/标签）渲染，语法符号淡显。保证落盘就是所见内容，同时手机上不用分屏预览。
3. **写入用临时文件 + rename**，防止进程被杀导致笔记截断。
4. **删除进回收站**（`.trash/`），不真删。
5. iOS 必须加 `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`，让 `Xiaoji/` 出现在「文件」App，否则纯本地没有安全网。
6. 中文搜索未来的坑：FTS5 `trigram` 要求 ≥3 字符，中文两字词搜不到；正确做法是逐字拆空格建索引。

## 设计定稿（用户确认）

四条决策：

1. **不做日期分组**。小记是流动的，分组会制造"今天还没写"的压力。
2. **主色走中性**：UI 全墨黑灰阶（#2C2C2A），唯一功能性强调色给标签/链接/光标，用系统蓝 #0A6CFF（深色下提亮为 #7DB2FF）。全 App 只有这一处彩色。
3. **列表密度两档可切**，不做连续调节：
   - 舒适（默认，对齐语雀小记）：摘要最多 5 行，元信息在正文下方
   - 紧凑（标题列表）：单行取首行，时间右对齐，**标签隐藏**（单行塞标签会把正文挤没）
4. **深色与浅色并列优先**，不是简单反色：底色 #161514 非纯黑，语法记号用固定色 #4F4D47 而非按透明度算，FAB 反相。

新增设计：设置页需要「列表密度」「主题（跟随系统/浅色/深色）」两项，存 `Xiaoji/settings.json`。

主页设计要点（已出图）：无底部 Tab、不用卡片（只有 0.5px/6% 分隔线）、摘要 5 行、标签条常驻顶部、时间只留必要精度（09:12 / 昨天 21:40 / N 天前 / 10月29日）、唯一入口是右下角深墨 FAB。

编辑页要点：顶栏只有返回·时间·菜单，无保存按钮，正文 16/1.7，**markdown 记号淡显（20% 灰）但文字仍是原文**，工具条贴键盘且点两次可取消。

## v1 范围最终裁定（用户拍板）

砍掉：**归档**（需求太窄，删除已覆盖）、回收站界面、长按菜单、已归档页。
保留并新增：**置顶**、**图片与附件**。

因此编辑器必须从「一个 TextField」升级为**块编辑器**（文本块 + 图片块 + 文件卡片块）——Flutter 的 TextField 没有原生附件机制（原生 iOS 有 NSTextAttachment），图片无法塞进文本框。这是本项目最大的技术成本，约 2–3 周。

图片存储方案：`Xiaoji/assets/<noteId>/1.jpg`，正文写相对路径 `![](assets/<noteId>/1.jpg)`。按笔记分目录，删笔记时整目录一起删，不留孤儿文件；整个 Xiaoji 目录拷走仍有效。

v1 最终功能：写（markdown 实时渲染 + 工具条 + 图片/附件块）、自动保存、时间线（舒适/紧凑两档）、标签 + 筛选、搜索、置顶、删除（进 trash/，无界面）、设置（主题/密度/导出）。

页面：主页（2 密度 × 明暗）、编辑页（明暗）、设置页 + 搜索态/空状态两个状态。共 3 页 + 2 状态。

## 第二轮：UI 还原设计稿（用户反馈 5 项）

用户反馈「整体 UI 与设计图差异很大」，另加 4 项具体问题。**关键发现：用户真机（PLK110 / Android 17 / 1272×2772 / 560dpi）一直连着 adb，可以直接装包截图验证**，比模拟器准得多。设备上有 3B15B601ERY00000。

修的东西：
1. **标签 chip 偏大且文字偏上** — 根因是用 padding 撑高度，字形盒子自带 leading 导致上下留白不等。改为固定 height + `Center(widthFactor: 1)` + `Text(height: 1)`。chip 从 ~32dp 收到 24dp、字号 12→11.5、描边 0.8→0.5。
2. **chips 下方缺分隔线** — 补 0.5px `dividerStrong`。
3. **紧凑密度要只显示首行** — 原来是把整段 `replaceAll('\n',' ')` 再截一行，等于「第一句 + 第二句开头」。改成 `plainSummary(...).split('\n').first`。
4. **长按图标新建小记** — `res/xml/shortcuts.xml` + manifest meta-data + `MainActivity.kt` 的 MethodChannel，Dart 侧 `lib/app/shortcuts.dart`（冷启动 consumeInitialAction / 后台 onNewIntent）。
5. **工具条太简陋** — 从字形字符（`H ☑ • " B I <> 链接 #:`）改成 12 个 Material 图标，分四组、可横滑，右侧固定「收起键盘 + 相机」，带激活态。

**踩到的坑（值得记住）**
- `Container(alignment: Alignment.center)` 会撑满父级约束，在 `Wrap` 里会变成一条通栏色块（`#交易` 标签被拉成整行）。要么用 `Center(widthFactor: 1)`，要么别给 alignment。
- 新建笔记用 `TextField.autofocus` 在路由动画/冷启动时**抢到焦点但唤不起 IME**，之后 requestFocus 也无效。正解：去掉 autofocus，改由 `initState` 里 post-frame + 260ms 延时主动 requestFocus。
- `adb shell input tap` 的 y 坐标要按 `截图像素 × (2772/1080)` 换算；弹层各项位置每次要重新从截图确认，凭记忆点会点到相邻项。中途设备自动转横屏会让所有坐标失效，先 `settings put system accelerometer_rotation 0`。

验证结果：analyze 零问题、183/183 测试通过、真机逐项截图确认（明/暗 × 两档密度 × 编辑页 × 快捷方式冷启动）。APK 48M，MD5 `c97a6de032cab12d93ec5352cad7d2bc`。



## 第三轮：编辑器双态 + 字号 + 图标

用户反馈 5 项。核心是把编辑器拆成**阅读态 / 编辑态**。

**新增 `lib/editor/markdown_view.dart`**：阅读态渲染器，把 markdown 记号**从输出里删掉**（不是淡显）。
与 `markdown_controller.dart`（编辑态，记号保留但 20% 灰）是两套，规则要同步改。
理由：编辑态一旦删字符，光标偏移就对不上文本，所以只能降饱和度；阅读态没有光标，可以随便删。

`EditorPage._editing`：已有笔记默认 false（阅读态），点正文任意块 → true 并聚焦该块末；新建笔记直接 true。
工具条右侧的「收起键盘」被**「完成」**取代（落盘 + unfocus + 回阅读态），语雀同款语义。

**字号整体上调约 1.2 倍**：设计稿按 296px 宽手机画的，直接当 dp 用必然偏小。
正文 13.5→16、编辑区 baseFontSize 15→17、页面标题 19→22、元信息 11→13、chip 11.5→13.5、chip 高 24→28。

**紧凑密度去掉缩略图**（用户提议）。理由：这一档唯一目标是扫标题，缩略图会把正文挤没。

**应用图标**：用 Python 脚本（纯 zlib 手写 PNG + 超采样抗锯齿）生成 5 个密度的
`ic_launcher.png` 与 `ic_launcher_foreground.png`，几何是「墨底 + 白色卡片轮廓 + 两白线 + 一蓝线」，
自适应图标声明在 `mipmap-anydpi-v26/ic_launcher.xml`。脚本在 `/tmp/gen_icon.py`（未入库）。

**测试**：因行为变更，`app_smoke_test` 与 `edge_case_editor_save_test` 需要先点进编辑态（已改，断言未放宽，
还加了 `expect(find.byType(TextField), findsNothing)` 锁住阅读态）。新增 `test/markdown_view_test.dart` 10 条
验证记号确实被剔除。最终 **193/193**。

**又一课**：`adb shell input tap` 的坐标要用 `sips -c` 裁图量，凭"图片显示比例"心算会偏 100px 以上，
连续点错会点到相邻控件（把相机当成完成点开附件菜单）。screencap 是 1272×2772，别拿聊天窗口里的显示尺寸换算。

## 第四轮：详情页 bug 群 + 图标重做

用户报 6 项。核心是编辑器逻辑。

**列表续行**（`block.dart` 的 `continuationFor()`，13 条单测）：
`1.` → `2.`（**保留原 `.`/`)` 分隔符**）、`-` → `-`、`- [ ]` → `- [ ]`（勾过的重置）、`>` → `>`、
**空的列表项回车 → 清掉标记退出列表**（这一步比语雀多做，语雀留空标记要用户手删减号）。

**换行没有续号 + 突然两个光标** 是同一个根因区域：`_handleTextChange` 在块尾检测到 Enter 后
只建了一个空块，没有续行；焦点用 `node.requestFocus()` 在分块那一帧会和旧块冲突。
改为 `FocusScope.of(context).requestFocus(node)`，并给 `_insertTextBlockAt` 加 `initial` 参数
（建块时就把标记写进去，避免"先建空块再补文字"的中间态）。

**主页摘要改用 markdown 渲染**：`excerptSource()` 取前 6 行（丢空行、丢图片行）→ `markdownSpans()`，
字号 16。搜索时退回 `highlightSpans` 纯文本（要高亮）。测试断言随之从"纯文本相等"变为
"标题仍是标题"。

**标签候选**：`_editTags` 改成 StatefulBuilder 对话框，顶部输入框 + 下方「已有标签」Wrap，
点 chip 在 controller 文本里增删（上限 12 个，按频次）。

**图标重做**：从"文档卡片"改成「一支 45° 的笔 + 一条蓝色墨线」。脚本加了多边形填充（射线法），
笔身是五边形（笔尖 + 笔杆），中间切一道 INK 色缝让 48dp 下也能看出是笔。构图整体上移右移各约 4-6 单位居中。

**弹窗样式**：Material 3 默认是带色调的灰底 + 阴影，与「纸」冲突。补 `DialogThemeData`：
`backgroundColor: page`、`elevation: 0`、0.5px 描边、圆角 14。

**遗留**：没有撤销/重做（和语雀差得最明显的一处）。跨块撤销要自己维护快照栈，这轮没做。

测试 206/206（新增 13 条续行 + 摘要相关调整）。APK 已装真机，逐项截图验证：
有序续号 `1.` → `2.`、空项退出、无序续行、单光标、摘要标题渲染、标签候选、弹窗纸白。

## 图标构图修正（用户反馈"整体偏左"）

根因：**包围盒居中 ≠ 视觉居中**。纸是大块白色实心（视觉重），笔是细线（视觉轻），
按包围盒中心锚定后，重的纸落在偏左位置。修法：锚点改用「纸的中心」，
包围盒只算缩放比例；纸居中后笔向右上伸出，用轻元素平衡重元素——标准构图法。
凡是"一个大主体 + 小附属元素"的图标都适用这条：锚主体，不锚包围盒。
